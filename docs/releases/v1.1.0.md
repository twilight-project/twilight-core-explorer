## What this release is

**v1.1.0 adds the operator dashboard and the twilight.org design** to v1.0.0. It's the first release
deployed with the tag-based procedure, on the canonical domain **explorer.twilight.org**.

It's a minor release: the public API only gains a path (`GET /api/v1/operators/{slotId}/history`) and a
field (`paid7` on `/participants`), and nothing in `/api/v1` changes incompatibly.

---

## What's new

- **Operator dashboard** on every operator's overview: headline totals, key metrics, a main chart
  (distinct miners, paid, owed, kept, miners paid, new miners, enrolled, settlement latency) with a range
  slider, a table view and CSV export. Chain figures and the operator's own (attested) figures are
  labelled separately throughout.
- **`GET /api/v1/operators/{slotId}/history`**: the daily series behind the dashboard. It's DB-only, uses
  the same definitions as the operator verdict, and returns attested counts under `feed` with
  `provenance: "attested"`.
- **twilight.org design**: light by default, the brand colours, faces and header, and band-glyph icons.
  Every text and status colour pair passes WCAG AA in both themes, enforced by a test.

The dashboard and theme are by @runnerelectrode (#96, #97); review fixes by @AhmadAshraf2 and us are in #101. Full list in
[`CHANGELOG.md`](../../CHANGELOG.md).

## Deploying (runbook §13)

This replaces the untagged build that has been running. On the server, **before** the deploy block:

1. **DNS:** point `explorer.twilight.org` at the origin through Cloudflare (proxied), like
   `explorer.nyks.dev` today.
2. **`.env.devnet`** (never committed):
   ```
   EXPLORER_DOMAIN="explorer.twilight.org, explorer.nyks.dev"   # serve both during the cut-over
   NEXT_PUBLIC_SITE_URL=https://explorer.twilight.org
   CORS_ORIGINS=https://explorer.twilight.org
   ```
   `API_TRUST_PROXY` doesn't need setting: compose defaults it to `loopback,uniquelocal`.
3. **Clean tree:** the server has local changes from the untagged deploys (the Caddyfile at least). Move
   anything that matters into `.env.devnet`, then `git checkout -- .` so the deploy block's clean-tree
   check passes.

Then run the §13 deploy block with `TAG=v1.1.0`. It builds the images from the tag, stamps the version,
and recreates Caddy. Afterwards:

4. **Purge the Cloudflare cache**: Caching → Configuration → Purge Everything, for both zones.
5. **Verify from outside:**
   ```sh
   curl -s https://explorer.twilight.org/api/v1/status | jq .data.build   # version "v1.1.0" and the commit
   curl -s -o /dev/null -w '%{http_code}\n' https://explorer.twilight.org/api/v1/operators/3/history   # 200
   curl -s -o /dev/null -w '%{http_code}\n' https://explorer.twilight.org/_next/image  # 404
   ```

There are no database migrations in this release.

**Rollback:** check out the previous build and rebuild. There's no earlier tag deployed, so keep note of
the commit currently running (`git rev-parse HEAD` on the server) before deploying.

## Known limitations

As in v1.0.0, plus these dashboard follow-ups:
- Epochs without a recorded close time are left out of the history.
- The history query aggregates the full history on each request; a time window or cache will follow.
- The brand fonts load from twilight.org, so visitors' browsers also contact that host.
